工作流程

四步完成从导出 JSON 到可验证请求的迁移。

保留到原始集合的追溯信息，查看报告后再决定如何运行生成的请求。

01

选择输入

选择 v2.0/v2.1 集合 JSON，必要时加入环境和全局变量。v2.0 在内存中规范化，原文件保持不变。

02

分析

查看可转换请求、阻碍项、脚本和变量依赖图。此步骤不会调用您的 API。

03

选择策略

保留集合顺序、拆分独立请求，或仅导出报告。预览会说明为何某些请求必须按顺序运行。

04

导出并验证

从第一个请求开始运行 scenario.http。independent.http 中的请求可单独运行。需要行为一致性时再进行运行时比较。

功能

谨慎转换，并保留后续工作所需的上下文。

↗

独立请求保持独立

依赖图将独立请求与需要前序结果的步骤分开。您也可以保留完整顺序或仅生成报告。

◈

环境和脚本

映射已验证的变量作用域和 pm.* API。敏感值写入加入 .gitignore 的私有环境文件。

⌘

不悄悄降级

只有元数据充足时才导出 GraphQL、gRPC 和 WebSocket。无法保留语义的内容连同来源位置写入 manual-review.md。

◎

迁移后差异比较

Newman 与 IntelliJ 跟踪适配器可比较方法、URL、请求头、请求体、状态和断言；敏感值以指纹形式隐藏。

▣

集成在 IDE 中

通过 Tools → Postman Migration Assistant 或 Ctrl+Alt+Shift+P 打开。预览、依赖图、输出和报告集中在同一流程。

◇

离线分析

集合读取、分析和导出均在本地进行。导入流程不会调用 Postman、JetBrains 或开发者服务器。

明确的边界

不支持的 JavaScript、复杂网络或异步行为，以及不完整的协议元数据可能需要人工处理。可转换不代表已在您的 API 上正确运行。兼容性仅针对 兼容性矩阵中列出的目标版本 ↗.

常见问题

帮助您快速判断的简明答案。

这个插件有什么用途？

Postman Migration Assistant 分析 Postman Collection v2.0/v2.1，并导出 IntelliJ HTTP Client 请求、环境文件、兼容脚本、来源映射及待检查事项报告。

需要重新导出 v2.0 集合吗？

不需要。插件接受 v2.0 和 v2.1；v2.0 在内存中规范化，原始文件不会被修改。

为什么有些请求必须从头运行？

scenario.http 中的请求可能使用前面生成的 token、ID 或变量，因此必须按顺序执行。independent.http 中的请求可以单独或并行运行。

97.2% 表示请求运行成功率吗？

不是。这是静态转换覆盖率：20 个公开集合的 2,582 个可执行请求中有 2,510 个可转换。仍须在目标 API 上进行运行时测试。

集合会上传到服务器吗？

导入期间不会。分析和导出在本地执行。运行生成的 .http 文件时，IntelliJ HTTP Client 才会向您配置的 API 发送请求。

支持 GraphQL、gRPC 和 WebSocket 吗？

有条件支持。GraphQL 需要 query；gRPC 需要 URL、service/method 和 message；WebSocket 需要 URL 与消息序列。信息不完整的请求会标记为人工检查。

Free 和 Pro 分别包含什么？

Free 分析完整集合并导出安全的独立基础请求。Pro 还会保留受支持的脚本、依赖场景、高级 OAuth2 和 HTTP 运行时语义，并提供差异验证。不受支持的行为在两个版本中都需要人工检查。

目前面向哪个 IDE 版本？

1.0 版本面向 IntelliJ IDEA Ultimate 2025.3.2 (IU-253.30387.90)。请查看兼容性矩阵中的最新证据。尚未宣布支持更广泛的 IDE 或操作系统。
