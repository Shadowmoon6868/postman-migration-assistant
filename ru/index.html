Процесс

От экспортированного JSON до проверяемых запросов за четыре шага.

Сохраняйте связь с исходной коллекцией и выбирайте способ запуска после просмотра отчёта.

01

Выберите файлы

Укажите JSON коллекции v2.0/v2.1, при необходимости окружение и глобальные переменные. v2.0 нормализуется в памяти; исходный файл не меняется.

02

Анализ

Просмотрите преобразуемые запросы, ограничения, скрипты и граф зависимостей переменных. На этом шаге API не вызывается.

03

Выберите стратегию

Сохраните порядок коллекции, отделите независимые запросы или экспортируйте только отчёт. Предпросмотр объяснит необходимость последовательного запуска.

04

Экспорт и проверка

Запускайте scenario.http с первого запроса. Запросы independent.http можно выполнять отдельно. При необходимости сравните поведение во время выполнения.

Демо на тестовых данных

Входные данные, результат и ограничения.

Пример основан на тестовой CRUD-коллекции из четырёх запросов. Видео создано на основе тестовых данных, а не записи интерфейса IntelliJ.

Описание видео и сцен

0–4 с: CRUD-коллекция содержит Login, Create, Read и Cleanup. 4–8 с: анализ находит зависимости token и customerId. 8–13 с: плагин экспортирует scenario.http, файлы окружения и отчёт. 13–18 с: запустите запросы с Login и проверьте результат в IntelliJ HTTP Client. Это иллюстрация на тестовых данных, а не доказательство работы нативного интерфейса.

Возможности

Осторожный перенос с контекстом для дальнейшей работы.

↗

Независимые запросы остаются независимыми

Граф зависимостей отделяет самостоятельные запросы от шагов, использующих предыдущие значения. Можно сохранить общий порядок или создать только отчёт.

◈

Окружения и скрипты

Переносятся сопоставленные области переменных и проверенные API pm.*. Секреты записываются в приватное окружение, добавленное в .gitignore.

⌘

Без скрытого упрощения

GraphQL, gRPC и WebSocket экспортируются только при достаточных метаданных. Непереносимые части перечислены в manual-review.md с указанием источника.

◎

Сравнение после переноса

Адаптеры трасс Newman и IntelliJ сравнивают метод, URL, заголовки, тело, статус и проверки. Секреты скрываются с помощью отпечатков.

▣

Внутри IDE

Откройте Tools → Postman Migration Assistant или нажмите Ctrl+Alt+Shift+P. Предпросмотр, граф зависимостей, файлы и отчёт доступны в одном процессе.

◇

Локальный анализ

Чтение коллекции, анализ и экспорт происходят на вашем компьютере. Во время импорта нет обращений к Postman, JetBrains или серверу разработчика.

Чёткие границы

Неподдерживаемый JavaScript, сложное сетевое или асинхронное поведение и неполные метаданные протокола могут требовать ручной работы. Возможность преобразования не доказывает успешный запуск в вашем API. Совместимость заявлена только для целевой версии в матрице совместимости ↗.

Тарифы

Начните с полезной версии Free. Переходите на Pro, когда важно сохранить поведение.

Классификация выполняется для каждого запроса. Free экспортирует простые запросы, а запросы, требующие Pro, перечисляются отдельно.

Сохранение поддерживаемого поведения и проверка соответствия.

  • ✓Поддерживаемые pre-request, response, assertion и внешние локальные скрипты через compatibility bridge.

  • ✓Все возможности Free, а также пробный период и подписка через Marketplace.

Окончательная цена подписки и условия пробного периода будут показаны JetBrains Marketplace до покупки.

Неподдерживаемый JavaScript, асинхронное или сетевое поведение и неполные метаданные остаются на ручной проверке в обеих версиях. Pro не выдаёт небезопасную догадку за поддерживаемое преобразование.

Частые вопросы

Короткие ответы для осознанного выбора.

Что делает плагин?

Postman Migration Assistant анализирует Postman Collection v2.0/v2.1 и экспортирует запросы IntelliJ HTTP Client, окружения, совместимые скрипты, карту источников и отчёт о том, что требует проверки.

Нужно ли повторно экспортировать коллекцию v2.0?

Нет. Плагин принимает v2.0 и v2.1, нормализует v2.0 в памяти и не изменяет исходный файл.

Почему некоторые запросы нужно запускать с начала?

Запросы scenario.http могут использовать токен, ID или переменную из предыдущего шага. Выполняйте их по порядку. Запросы independent.http можно запускать отдельно или параллельно.

Означает ли 97,2% успешную работу запросов?

Нет. Это покрытие статического преобразования: 2 510 из 2 582 исполняемых запросов в 20 публичных коллекциях. Нужна проверка во время выполнения на целевом API.

Загружается ли коллекция на сервер?

Не во время импорта. Анализ и экспорт выполняются локально. При запуске созданного файла .http IntelliJ HTTP Client отправляет запросы в настроенный вами API.

Поддерживаются ли GraphQL, gRPC и WebSocket?

При наличии данных. Для GraphQL нужен запрос, для gRPC — URL, сервис/метод и сообщение, для WebSocket — URL и последовательность сообщений. Неполные запросы помечаются для ручной проверки.

Что входит в Free и Pro?

Free анализирует всю коллекцию и экспортирует безопасные независимые базовые запросы. Pro сохраняет поддерживаемые скрипты, зависимые сценарии, расширенный OAuth2 и HTTP-семантику, а также добавляет differential verification. Неподдерживаемое поведение требует ручной проверки в обеих версиях.

Какая IDE сейчас поддерживается?

Версия 1.0 ориентирована на IntelliJ IDEA Ultimate 2025.3.2 (IU-253.30387.90). Актуальные доказательства см. в матрице совместимости. Более широкая поддержка IDE и ОС не заявлена.
