Quy trình

01

Chọn đầu vào

Chọn collection JSON v2.0/v2.1, environment và globals nếu cần. v2.0 được chuẩn hóa trong bộ nhớ; file gốc giữ nguyên.

02

Analyze

03

Giữ nguyên thứ tự, tách request độc lập hoặc chỉ xuất báo cáo. Preview giải thích vì sao một request cần chạy theo chuỗi.

Chạy scenario.http từ request đầu tiên. Request trong independent.http có thể chạy riêng. Đối chiếu runtime khi cần kiểm chứng tương đương.

Khả năng

Chuyển đổi có trách nhiệm, đủ ngữ cảnh để tiếp tục công việc.

↗

Không ép mọi request thành một chuỗi

Đồ thị phụ thuộc tách request độc lập khỏi bước dùng dữ liệu trước đó. Bạn cũng có thể giữ nguyên thứ tự hoặc chỉ tạo báo cáo.

◈

Environment và script

Các scope biến và API pm.* đã kiểm thử được ánh xạ. Giá trị nhạy cảm nằm trong private environment và được thêm vào .gitignore.

⌘

Không âm thầm hạ cấp

GraphQL, gRPC và WebSocket chỉ được xuất khi đủ metadata. Phần không bảo toàn semantics nằm trong manual-review.md kèm vị trí nguồn.

◎

Đối chiếu sau migration

Adapter Newman và IntelliJ trace so sánh method, URL, header, body, status và assertion; dữ liệu nhạy cảm được che bằng fingerprint.

▣

Điều khiển trong IDE

Mở Tools → Postman Migration Assistant hoặc nhấn Ctrl+Alt+Shift+P. Preview, dependency graph, output và report nằm trong một luồng.

◇

Phân tích offline

Đọc, phân tích và xuất file cục bộ. Luồng import không gọi Postman, JetBrains hay máy chủ của nhà phát triển.

Ranh giới rõ ràng

JavaScript ngoài tập hỗ trợ, hành vi mạng/async phức tạp và metadata protocol thiếu có thể cần sửa thủ công. Convertible không chứng minh request chạy đúng trên API của bạn. Compatibility chỉ công bố cho target trong compatibility matrix ↗.

Câu hỏi thường gặp

Câu trả lời ngắn, đủ để quyết định.

Plugin này làm gì?

Postman Migration Assistant phân tích Postman Collection v2.0/v2.1 rồi xuất request IntelliJ HTTP Client, environment, script tương thích, source map và báo cáo phần cần rà soát.

Tôi có cần export lại collection v2.0 không?

Không. Plugin nhận v2.0 và v2.1. v2.0 được chuẩn hóa trong bộ nhớ, file nguồn không bị sửa.

Vì sao một số request phải chạy từ đầu file?

Request trong scenario.http có thể dùng token, ID hoặc biến do request trước tạo. Hãy chạy theo thứ tự. Request trong independent.http có thể chạy riêng hoặc song song.

97,2% có nghĩa là request chạy thành công?

Không. Đây là tỷ lệ chuyển đổi tĩnh: 2.510 trong 2.582 request thực thi thuộc 20 collection công khai. Vẫn cần kiểm thử runtime trên API đích.

Collection có bị tải lên máy chủ không?

Không trong lúc import. Phân tích và xuất file diễn ra cục bộ. Khi bạn chạy file .http, IntelliJ HTTP Client gửi request đến API đã cấu hình.

Có hỗ trợ GraphQL, gRPC và WebSocket không?

Có điều kiện. GraphQL cần query; gRPC cần URL, service/method và message; WebSocket cần URL và message sequence. Request thiếu dữ liệu được chỉ định rà soát thủ công.

Free và Pro gồm những gì?

Free phân tích toàn bộ collection và xuất request cơ bản độc lập an toàn. Pro bảo toàn script, scenario phụ thuộc, OAuth2 và HTTP runtime semantics đã hỗ trợ, đồng thời thêm differential verification. Unsupported behavior vẫn cần manual review ở cả hai.

Hiện nhắm IDE nào?

Phiên bản 1.0 nhắm IntelliJ IDEA Ultimate 2025.3.2 (IU-253.30387.90). Xem compatibility matrix để biết bằng chứng mới nhất. Chưa công bố hỗ trợ rộng cho IDE hoặc hệ điều hành khác.
